## 统一高吞吐档

| 项目 | 要求 |
|---|---|
| 部署策略 | 对应 H200 High-Throughput；卡数保留用户覆盖值 |
| 输入 | 75k = 76,800 tokens/request |
| 输出 | 1k = 1,024 tokens/request，含 reasoning + completion |
| 缓存 | 输入 token 命中目标 90%，另报实测比例 |
| 正式样本 | **200 条**，不含预热和缓存预置 |
| 到达率 | 只测 `request_rate=inf` |
| 客户端并发 | 不设 concurrency cap，检查连接池/信号量没有隐式限流 |
| 不执行 | 不增加按第一阶段实测速率发压的第二个 measured 阶段 |
| 输出 | 实际完成 RPS、输入/命中/未命中/输出/总 TPM、延迟、成功率、单卡月收入 |

用户最初提到统一档 100 条，随后明确“样本数按200”。**最新要求为统一档及每个 SLA 点均 200 条**；早期执行草稿可能仍用 100 条，恢复前需同步执行器并重建相应数据。不要把旧草稿当成后续用户确认。

## SLA 档

各模型使用对应 H200 Low-Latency 配置。每个正式速率点 200 条，按平均值判定，不设 P95 TTFT 门槛。

| 模型 | 输入 tokens/request | 输出 tokens/request | 输入 token 缓存命中目标 | Mean TTFT | Mean TPOT |
|---|---:|---:|---:|---:|---:|
| DeepSeek V4.1 Flash | 8,000 | 1,252 | 93.2% | **<2.000 s** | ≤20.000 ms/token |
| DeepSeek V4 Flash | 22,016 | 514 | 79.6% | ≤1.000 s | ≤25.400 ms/token |
| DeepSeek V4 Pro | 49,664 | 948 | 86.8% | ≤2.860 s | ≤22.200 ms/token |
| GLM 5.3 | 72,125 | 1,095 | 94.532% | ≤1.397 s | ≤1000/60 ms/token |
| GLM 5.3 Flash | 73,835 | 1,447 | 92.56% | ≤2.000 s | ≤1000/30 ms/token |

- 仅带 k/K 的数字按 1,024 换算：21.5K=22,016；48.5K=49,664。8,000、72,125、73,835 等已给出的数字保持原值。
- GLM 的 60 tok/s 和 30 tok/s 转为 TPOT 阈值，分别约 16.666667、33.333333 ms；判定保留足够精度。
- V4.1 旧参考 P50 0.81 s、P95 2.55 s、130 tok/s 已被最新 **平均 TTFT<2 s、平均 TPOT≤20 ms** 替代，不再作为准入条件。
- 使用固定长度合成负载代表用户给定均值，不宣称复现了真实业务的长度分布。
- 有限到达率采用确定性 open-loop、无客户端并发上限；搜索最高通过点和相邻失败点，保持每点数据、seed 和计时口径一致。

用户提供的工具/结构化错误率只是背景参考：V4.1 工具约0.93%；GLM 5.3 工具约0.28%、结构化约0.88%；GLM 5.3 Flash 工具约2.27%，其他未提供稳定样本。合成吞吐测试不验证这些指标，也不据此给质量准出结论。
