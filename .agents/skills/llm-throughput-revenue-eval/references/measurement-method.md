# 测量与 SLA 判定

计量原则可复用；下文200条样本、搜索预算等具体数值属于本轮五模型计划。用于其他任务时采用该任务最新确认值，不强制沿用本轮参数。

## 数据和缓存

1. 使用实际模型 tokenizer 精确计数。保留 tokenizer 身份、seed、输入数据哈希及每条输入/输出长度。用文本接口时计入模板和重分词后的长度，不用字符数估 token。
2. 本轮可用本地 SGLang 原生 `/generate` + `input_ids` 精确控制合成输入；必须注明结果不包含 router、Chat 模板和生产接入开销。更换协议则单列，不能拼接结果。
3. 固定目标输出总量，包含 reasoning + completion；记录 temperature、thinking、EOS/stop 处理和固定长度方法。若使用 `ignore_eos` 或随机 token，要说明这不是自然业务输出分布或质量评测。
4. 缓存目标是 `sum(cached_input_tokens)/sum(input_tokens)`。不把“90%共享前缀”“99%请求复用”直接等同实际 token 命中率。
5. 使用相同共享前缀、独立尾部及固定 seed。可按 KV 页对齐混用相邻前缀长度，以逼近整体目标。声明预热/预置缓存数量与成本，正式计时前完成，不计入正式样本。
6. 同一 SLA 场景的每个速率点复用相同数据；在本任务独占实例清缓存后重新预置，避免上点留下全输入缓存。DP attention 时验证各调度单元都获得正确前缀缓存，不能只预置一个 rank。
7. 用请求 `cached_tokens` 与服务端计量交叉核对，记录目标、实际值及预先定义的容差（依据页粒度、总 token 数）。超差点不当作满足该缓存目标的结果。

共享前缀必须实际支持前缀缓存；即使构造正确，调度冷启动、驱逐、路由和 KV 压力也可能改变命中。合成 random token 还会影响 MTP acceptance rate；不能把该收益当真实业务收益。

## 发压与计时

- `request_rate=inf`：所有正式请求尽快提交；不加 semaphore/concurrency cap，检查 HTTP 连接池默认上限、文件句柄及发压器 CPU 没有限速。保留服务端安全上限并记录队列。
- SLA 点：有限确定性 open-loop，按 `t0+i/rate` 安排请求，不因上一个请求未完成而变成闭环。记录计划、实际提交时刻和 dispatch lag，验证实际发出速率。
- 正式窗口从第一次正式提交开始到最后一个正式请求终止，包含填充、排空和失败等待，不截取更好看的中段。预热、缓存预置单独记账。
- 完成 RPS 为成功完成数/窗口秒数；TPM 根据实际成功 token 总量计算，不使用 offered RPS 直接乘标称长度替代。
- 每请求 TTFT：提交到首个实际输出 token 的时间，排除空 SSE/usage 事件。
- 每请求 TPOT：`(最后输出token到达时间 - 首输出token到达时间)/(实际输出tokens-1)`；0或1 token 时为 N/A，不当作0。SSE 一次可能带多个 token，使用累计 token 数，不能用 chunk 数。
- SLA 使用每个有效成功请求的 TTFT、TPOT 的算术均值，不改用 token 加权平均或分位数；同时要求正式请求全部成功，不能删掉慢请求使均值达标。
- 可以另报 P50/P95/P99 供观察，但本轮不以它们判定。保留失败率、超时、截断、重启/OOM和 GPU/KV/queue 证据。

外层HTTP结束时间可能晚于最后token；因此 `E2E≈TTFT+TPOT×(out−1)` 只用于带协议尾部差异的合理性检查，不强制逐位相等。

## 搜索 SLA 边界

固定每点样本数和到达方式，用独立的低延迟配置搜索：

1. 从保守速率开始。通过后提高速率；仅延迟未达标时降低速率，形成通过/失败区间。
2. 区间内细化，报告最高通过点、相邻失败点及各自实际完成 RPS/TPM。不同速率必须是独立200条正式样本，不混成一个平均点。
3. 本轮可沿用倍增/折半加二分的搜索预算：最多12点；区间宽度≤`max(通过目标RPS×10%, 0.005 RPS)`时停止；低速探索下限0.015625 RPS。这是可调整的执行预算，不是数学定理或额外 SLA。
4. 达到预算仍全通过，写“至少达到最高已测点，尚无失败上界”；全部失败，写“已测点无达标点”。不伪称找到全局最大值。
5. OOM、崩溃、路由/客户端异常、缓存目标失效或发压器跟不上属于测量/稳定性问题，先停止并诊断，不把它们直接作为纯 TTFT/TPOT 失败上界。

通过需要同时满足：200/200成功、输出/数据要求有效、缓存目标在声明容差内、发压速率可信、平均TTFT和平均TPOT达标、服务无重启。边界重复验证能增加信心；若未做重复实验或真实流量回放，明确这一限制。

## 证据与暂停

逐点保存配置身份、正式样本 manifest、请求级 token/时间/状态、服务端指标、启动前后进程身份、实际运行时长及判定原因；原始证据与报告关联。需要脱敏的端点、凭据只保留必要的环境引用。

暂停时先停止队列防止拉起下一个模型，再停止发压，最后对已核验所有权的引擎优先发送正常终止信号。核对进程退出和GPU释放；未发送/部分完成的点记为中断，已有完成点保留。恢复用新的 run ID，先对照最新计划检查旧脚本默认值，不拼接跨代次指标。
